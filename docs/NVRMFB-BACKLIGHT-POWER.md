# NVRMFB backlight power requests

`linear-brightness` and `brightness` requests from the display slider update the user target. After NVKMS applies a user request successfully, NVRMFB writes a changed target to the `/options` property `nullmoth-backlight` as one byte in the range 0–100. On the next handler creation, NVRMFB reads a valid value, initializes the display parameters to it, and queues an asynchronous restore. A missing or invalid value falls back to the hardware's initial level. Whole-display power requests from AppleBacklightDisplay do not replace the user target; temporary dimming is not saved. The existing 5% hardware floor remains in effect, so a saved 0% target is sent to hardware as 5%.

Run `python3 tools/check_nvrmfb_backlight_target.py` for request routing and `python3 tools/test_nvrmfb_backlight_persistence.py` for extracted `withRM`, `setDisplay`, and `applyFire` behavior. These checks use fixtures and do not build the kext or verify that `/options` survives a physical restart. The RTX 5080 Laptop/macOS 26.7 display and lid behavior were reported by the submitter; persistence across restart remains a hardware check.

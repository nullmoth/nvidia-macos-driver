# NVRMFB backlight power requests

`linear-brightness` and `brightness` requests from the display slider update the user target. After NVKMS applies a user request successfully, NVRMFB writes a changed target to the `/options` property `nullmoth-backlight` as three bytes: version 1 followed by the little-endian 16-bit logical target. Legacy one-byte 0–100 values remain readable. On the next handler creation, NVRMFB reads a valid value, initializes the display parameters to it, and queues an asynchronous restore. A missing or invalid value falls back to the hardware's initial level. Whole-display power requests from AppleBacklightDisplay do not replace the user target; temporary dimming is not saved. The existing 5% hardware floor remains in effect, so a saved 0% target is sent to hardware as 5%.

Run `python3 tools/check_nvrmfb_backlight_target.py` for request routing and `python3 tools/test_nvrmfb_backlight_persistence.py` for extracted `withRM`, `setDisplay`, and `applyFire` behavior. These checks use fixtures and do not build the kext or verify that `/options` survives a physical restart. The RTX 5080 Laptop/macOS 26.7 display and lid behavior were reported by the submitter; persistence across restart remains a hardware check.

## Parameter precision and backend limits

The four IODisplay brightness and conversion-probe parameters advertise a logical range of 0–65535. IOKit normalizes its float API using each parameter's advertised min/max; 65535 is this driver's precision choice, not an Apple-mandated range or an additional hardware capability. Both real parameter values stay synchronized after a user request. Temporary power requests do not overwrite either user value, and conversion probes only update the opposite probe.

The logical target remains unquantized through probes, pending requests and restart persistence. Only the final NVKMS call rounds it to integer percent, as required by NVIDIA's backlight interface. The existing upstream 5% output floor is retained; it is not a measured per-panel minimum. No key steps, device-model branches, smoothing or perceptual curve are implemented. BrightnessKeys and macOS retain ownership of keyboard events and stepping policy. These changes remove the driver's percent-precision loss; keyboard/slider behavior on physical hardware remains to be verified.

Public contracts: [Apple IODisplay float normalization](https://github.com/apple-oss-distributions/IOKitUser/blob/main/graphics.subproj/IODisplayLib.c), [IODisplay parameter handling](https://github.com/apple-oss-distributions/IOGraphics/blob/main/IOGraphicsFamily/IODisplay.cpp), and [NVIDIA integer-percent backlight](https://github.com/NVIDIA/open-gpu-kernel-modules/blob/main/kernel-open/nvidia-modeset/nvidia-modeset-linux.c).
